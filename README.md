# FactoryMind

**Agentic AI 自主製造營運治理平台** — AI 競賽專案。

中小型製造業遇到設備故障、急單插入或缺料時,多半仰賴資深主管憑經驗判斷。FactoryMind 讓系統整合工廠狀態、提出候選方案,先在**虛擬工廠**(模擬式數位分身)中試跑、檢查企業規則,再依授權提出建議或執行,並保存完整的決策依據。

競賽情境為塑膠射出廠(接單式、高混線製造);所有操作作用於虛擬工廠,不含真實設備控制。

## 核心設計

- **AI 理解與協調、求解器精確計算、數位分身模擬驗證** — LLM 負責語意理解與說明,數字一律由計算工具產生。
- **硬規則 / 軟政策分離** — 硬規則(產能、相容性、工時上限)由程式檢查,先排除不可接受的方案;軟政策(如策略客戶優先)用來比較剩餘方案。
- **模擬、核准、執行分開** — 三者是不同動作;執行前重新檢查狀態與授權是否仍有效。
- **Decision Trace** — 選擇、拒絕、核准、執行與失敗都能沿同一筆事件追查。
- **Human-in-the-loop** — 由 AI 建議、人員核准開始,漸進提高自主程度。

## 治理主線

```
偵測 → 評估 → 提案 → 模擬評估 → 決策 → 稽核回報
```

## 五個 AI 角色

| 角色 | 職責 |
| --- | --- |
| Monitor 監控 | 受理事件與主管問題,判斷事件類別、影響範圍、資料缺口 |
| Maintenance 維修 | 彙整維修回報與資訊缺口;不自行推定故障原因或復機時間 |
| Production 生產 | 評估受影響訂單、產能與交期缺口 |
| Schedule 排程 | 產生結構化候選方案與模擬請求 |
| Report 報告 | 產出主管摘要、選擇與排除理由;不捏造缺失的數字 |

角色是職責分工,不是固定五次模型呼叫;確定性檢查交給程式。

## 系統架構

1. **決策介面層** — 主管總覽、事件工作台、方案比較、AI 對話、企業政策、結案報告
2. **事件處理與 AI 協作層** — 固定治理主線,依需要調用五個角色
3. **計算與執行工具層** — 排程、副本模擬、硬規則檢查、執行前重驗、虛擬工廠套用與核對
4. **資料與紀錄層** — 工廠快照、事件、政策、授權、候選方案、計算結果、執行證據

部署採模組化單一後端,重型模擬由背景工作執行。

## 規劃技術

| 用途 | 技術 |
| --- | --- |
| Multi-Agent 編排 | LangGraph / LangChain |
| LLM | GPT、Claude 等 |
| 排程最佳化 | Python 排程求解器 |
| 數位分身模擬 | SimPy(離散事件模擬) |
| 後端 | FastAPI、PostgreSQL |
| 前端 | React / Next.js、Chart.js |

## 目前進度

底層(不呼叫 AI 的部分)已可運作,位於 `backend/factorymind/`:

| 模組 | 內容 |
| --- | --- |
| `models.py` | 工廠快照:機台、模具、塑料、產品、客戶、工單、班別 |
| `plan.py` | 候選方案與評估結果的資料契約 |
| `replay.py` | 虛擬工廠試跑:班別、序列相依換模、模具不可同時在兩台機上 |
| `rules.py` | 硬規則檢核:模具—機台相容、停機、缺料、加班上限與預算、已開工工單、延誤上限 |
| `evaluate.py` | 方案評估介面:計算是否成功、是否可行、是否過硬規則分開回報 |
| `dispatch.py` | 派工法則排程器(FIFO／交期／策略客戶優先),作為規則基準 |
| `optimize.py` | 局部搜尋排程器:從派工法則出發搬移／對調工單,依企業順位改進;結果為局部最佳,不保證全域最佳 |
| `ranking.py` | 依企業順位與門檻逐一比較方案 |
| `events.py` | 擾動事件:機台停機、急單,產生新版本快照 |
| `scenarios/demo.py` | 合成的射出廠與示範政策 |

治理主線與決策介面(記憶體內運作,重啟即重置):

| 模組 | 內容 |
| --- | --- |
| `candidates.py` | 候選方案產生器:轉機重排、局部搜尋、加班、急單外包 |
| `governance.py` | 虛擬工廠與治理主線:自動發出擾動事件、評估、提案、試跑、排序、等待核准;核准綁定方案與版本,套用前重驗,狀態一變方案即過期;維修回報後才結案;全程留下處理歷程 |
| `api.py` | FastAPI:工廠狀態、事件、核准／退回／重新評估／維修回報 |

前端 `frontend/`(Next.js)是主管的**決策介面**:營運總覽(要不要介入、目前排程、政策、機台)與事件工作台(發生什麼事、系統建議與理由、會改動哪些工單、核准或退回、方案比較與排程預覽、必要任務、處理歷程)。

尚未開始:LLM 角色與 AI 對話、資料庫(持久保存)、登入與權限、ERP/MES 連接器、企業政策編輯、正式結案報告。所有資料為合成資料。

## 使用方式

### 1. 第一次安裝

需要 Python 3.10 以上、Node.js 20 以上。

```bash
# 後端
cd backend
python3 -m venv .venv
.venv/bin/python -m pip install -e ".[dev]"

# 前端
cd ../frontend
npm install
```

### 2. 啟動

後端與前端要同時開著,各用一個終端機。

```bash
# 終端機 A:虛擬工廠與 API(埠 8000)
cd backend
.venv/bin/python -m uvicorn factorymind.api:app --port 8000
```

```bash
# 終端機 B:決策介面(埠 3000)
cd frontend
npm run dev
```

瀏覽器開啟 <http://localhost:3000>。停止時在各終端機按 `Ctrl+C`。

### 3. 操作流程

1. **按右上角「開始運轉」。** 虛擬工廠約 5 秒後自己發生第一個事件:射出機 IM-02 停機,同時進來一張策略客戶急單。畫面會自動跳到這個事件。
2. **等系統算完。** 進度條依序走過偵測、評估、提案、模擬評估,幾秒後停在「決策」,狀態顯示「等你決定」。這段期間工廠不會被改動。
3. **看系統建議。** 最上方是建議方案與四個數字:策略客戶是否準時、逾期幾張、改動幾張工單、額外成本。點「會改動 N 張工單」可看每張工單原本在哪、調整後在哪。
4. **比較其他方案(可略過)。** 下方表格列出所有候選方案;✕ 標在讓該方案落選的那一項,滑鼠移上去有說明。點任一列只是預覽它的排程,不會改變建議,也不會套用。
5. **做決定。**
   - **核准**:採用系統建議,排程在虛擬工廠生效。
   - **退回**:填寫原因後退回,工廠不變;之後可改選其他方案或重新評估。
   - **改選這個方案**:先在表格點選另一個合規方案,再核准它。違反硬規則的方案沒有核准按鈕。
6. **回報維修。** 有機台停機的事件,核准後狀態是「生產已調整・設備維修中」。按「回報已復機」後,機台恢復可用,事件才結案。
7. **下一個事件。** 結案約 30 秒後,虛擬工廠會自己再發生一個隨機的停機或急單。不想等就按「發生事件」。

### 4. 畫面與按鈕

| 位置 | 說明 |
| --- | --- |
| 開始運轉 / 暫停 | 虛擬工廠是否會自動發生事件 |
| 發生事件 | 立刻發生下一個事件,不必等待 |
| 重設 | 清掉所有事件與決策紀錄,回到原始工廠 |
| 左側「營運總覽」 | 有沒有需要你處理的事、目前生效的排程、企業政策、機台與生產流程 |
| 左側「事件」清單 | 每個事件與它的狀態;點選進入該事件 |
| 排程圖 | 橫軸是時間,每列一台機台;藍色是一般客戶、橘色加 ★ 是策略客戶、斜線是換模或換色、灰底是非上班時間。滑鼠移到工單上可看明細 |
| 方案 / 事件前 | 在方案排程與事件發生前的排程之間切換;事件前的畫面會框出排在停機機台上的工單 |
| 處理歷程 | 展開可看系統與人員做過的每一步,包含退回與過期 |

事件狀態:

| 狀態 | 意思 | 你要做的事 |
| --- | --- | --- |
| 系統處理中 | 正在試跑方案 | 等幾秒 |
| 等你決定 | 已有建議 | 核准或退回 |
| 已退回建議 | 你退回了建議 | 改選其他方案,或重新評估 |
| 方案已過期 | 評估後工廠狀態變了(例如另一台機復機) | 按「重新評估」 |
| 沒有合規方案 | 所有方案都不可行或違規 | 調整條件或補資料後重新評估 |
| 生產已調整・設備維修中 | 排程已生效,維修尚未回報 | 回報已復機 |
| 已結案 | 排程生效且必要任務都完成 | 無 |

### 5. 常見狀況

- **畫面顯示「連不到虛擬工廠」**:後端沒有啟動,或不在埠 8000。先啟動終端機 A。後端若在別的位址,啟動前端時加上 `FACTORYMIND_API=http://主機:埠 npm run dev`。
- **瀏覽器顯示 `ERR_CONNECTION_REFUSED`**:前端沒有啟動。在 WSL 上若 `localhost` 連不到,改用 `npm run dev -- -H 0.0.0.0` 啟動,並以 `hostname -I` 顯示的位址開啟。
- **埠 3000 被占用**:Next.js 會自動改用 3001,以終端機顯示的網址為準。
- **重啟後端後事件都不見了**:目前狀態只存在記憶體,重啟即回到原始工廠。
- **想調整事件發生的間隔**:啟動後端時設定環境變數,單位為秒,例如 `FACTORYMIND_FIRST_EVENT_S=2 FACTORYMIND_NEXT_EVENT_S=10`。

### 6. 目前的限制

- 所有資料為合成資料;機台用途與產品品名也是為示範情境編寫的。
- 虛擬工廠的時間不會前進:每個事件都發生在第 0 分鐘,工單不會隨時間完成,連續處理多個事件會越來越不貼近實際。
- 沒有登入與權限,核准者固定為「生產主管」。
- 尚未接上語言模型,所有文字與建議都由程式產生。

## 開發

```bash
cd backend
.venv/bin/python -m pytest             # 後端測試
.venv/bin/python -m factorymind.demo   # 在終端機印出主情境的方案比較,不需要啟動伺服器
```

```bash
cd frontend
npx tsc --noEmit    # 型別檢查
npm run build       # 正式建置
```

時間單位一律為分鐘(自快照時間起算),金額為新台幣。API 啟動後可在 <http://localhost:8000/docs> 查看所有端點。
