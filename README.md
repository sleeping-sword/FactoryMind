# FactoryMind

**Agentic AI 自主製造營運治理平台** — AI 競賽專案。

中小型製造業遇到設備故障、急單插入或缺料時,多半仰賴資深主管憑經驗判斷。FactoryMind 讓系統整合工廠狀態、提出候選方案,先在**虛擬工廠**(模擬式數位分身)中試跑、檢查企業規則,再依授權提出建議或執行,並保存完整的決策依據。

競賽情境為塑膠射出廠(接單式、高混線製造);所有操作作用於虛擬工廠,不含真實設備控制。

## 核心設計

- **AI 理解與協調、求解器精確計算、數位分身模擬驗證** — LLM 負責語意理解與說明,數字一律由計算工具產生。
- **硬規則 / 軟政策分離** — 硬規則(產能、相容性、工時上限)由程式檢查,先排除不可接受的方案;軟政策(如策略客戶優先)用來比較剩餘方案。
- **模擬、核准、執行分開** — 三者是不同動作;執行前重新檢查狀態與授權是否仍有效。
- **Decision Trace** — 選擇、拒絕、核准、執行與失敗都能沿同一筆事件追查。
- **Human-in-the-loop** — 由 AI 建議、人員核准開始,漸進提高自主程度。

## 治理主線

```
偵測 → 評估 → 提案 → 模擬評估 → 決策 → 稽核回報
```

## 五個 AI 角色

| 角色 | 職責 |
| --- | --- |
| Monitor 監控 | 受理事件與主管問題,判斷事件類別、影響範圍、資料缺口 |
| Maintenance 維修 | 彙整維修回報與資訊缺口;不自行推定故障原因或復機時間 |
| Production 生產 | 評估受影響訂單、產能與交期缺口 |
| Schedule 排程 | 產生結構化候選方案與模擬請求 |
| Report 報告 | 產出主管摘要、選擇與排除理由;不捏造缺失的數字 |

角色是職責分工,不是固定五次模型呼叫;確定性檢查交給程式。

## 系統架構

1. **決策介面層** — 主管總覽、事件工作台、方案比較、AI 對話、企業政策、結案報告
2. **事件處理與 AI 協作層** — 固定治理主線,依需要調用五個角色
3. **計算與執行工具層** — 排程、副本模擬、硬規則檢查、執行前重驗、虛擬工廠套用與核對
4. **資料與紀錄層** — 工廠快照、事件、政策、授權、候選方案、計算結果、執行證據

部署採模組化單一後端,重型模擬由背景工作執行。

## 規劃技術

| 用途 | 技術 |
| --- | --- |
| Multi-Agent 編排 | LangGraph / LangChain |
| LLM | GPT、Claude 等 |
| 排程最佳化 | Python 排程求解器 |
| 數位分身模擬 | SimPy(離散事件模擬) |
| 後端 | FastAPI、PostgreSQL |
| 前端 | React / Next.js、Chart.js |
